# Documentation quality

Quality combines editorial judgment with repeatable validation.

## Quality stack

| Tool or review | Checks |
| --- | --- |
| Technical review | Product behavior, examples, prerequisites, limitations |
| Editorial review | Structure, clarity, terminology, voice, accessibility |
| Vale | Style and terminology rules |
| CSpell | Spelling and approved vocabulary |
| markdownlint | Markdown source consistency |
| Lychee | Broken links |
| MkDocs strict build | Navigation, configuration, and build validity |

## Active voice

Active voice usually makes procedures clearer because the actor and action are explicit. Passive voice remains useful when the actor is unknown, irrelevant, or intentionally de-emphasized. The goal is clarity, not a mechanical ban on passive constructions.

## Definition of done

A page is ready when its technical claims are reviewed, its task flow is complete, required examples and assets work, terminology is consistent, automated checks pass, and the published output has been verified.
