# API documentation practice

Good API documentation is a connected developer journey rather than a collection of endpoint pages.

## Documentation layers

| Layer | Developer question |
| --- | --- |
| Overview | What can I build with this API? |
| Get started | How do I make a successful first request? |
| Concepts | How do the resources and lifecycle work? |
| Tutorials | How do I complete a real integration task? |
| Reference | What exactly does this endpoint accept and return? |
| Errors | Why did the request fail and what should I do? |
| Webhooks | How does my application receive asynchronous changes? |

## Review checklist

Verify authentication, permissions, URLs, methods, parameters, examples, response fields, error behavior, version assumptions, and links. Code samples should be executable or clearly marked as illustrative.
